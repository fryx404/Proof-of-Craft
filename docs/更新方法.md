# 更新方法

GitHub Pages への公開手順とトラブル対応。
デザインの変更箇所は [デザインメモ.md](デザインメモ.md) を参照。

## GitHub Pages への公開手順

`git init` / `commit` / `remote add` までは設定済みです。初回は push から始めます。

```bash
git push -u origin main
```

初回はブラウザが開いて GitHub のログインを求められます（Git Credential Manager）。

続いてリポジトリの **Settings → Pages** で以下を設定します。

- Source: `Deploy from a branch`
- Branch: `main` / `/ (root)`

1〜3分後に https://fryx404.github.io/Proof-of-Craft/ で公開されます。

### 以降の更新

```bash
git add .
git commit -m "Add FT_NewTool"
git push
```

`tools.json` を編集して push するだけで反映されます。

### push 前の確認

`tools.json` は `fetch` で読んでいるため、`index.html` をダブルクリックで開くと CORS で失敗します。
必ず簡易サーバー経由で確認してください。

```bash
npx serve .
# または
python -m http.server 8000
```

### うまくいかないとき

- **Pages が 404** → リポジトリが Public になっているか確認（Private は無料プランでは公開されない）
- **ページは出るがカードが空** → `tools.json` がリポジトリ直下に push されているか確認
- **サムネイルが出ない** → ツール側リポジトリが Public か、`image` の raw URL のブランチ名が合っているか確認
- **デザインが古いまま** → ブラウザのキャッシュ。スーパーリロード（Ctrl + Shift + R）を試す
- **一瞬だけ白く光ってからダークになる** → `index.html` の `<head>` 先頭にあるテーマ確定スクリプトが消えていないか確認

## デザインを変えたいとき

詳細は [デザインメモ.md](デザインメモ.md) にまとめてあります。要点だけ:

- **色** — `assets/style.css` 冒頭のカラートークンだけを編集する。それ以降にカラーコードは1つも書かれていないので、トークンを変えれば全体が追従する
- **テーマ** — ライト / ダーク / システム連動の3モード。切替UIとロジックは `index.html` 内のインラインスクリプト
- **見出しの太さ・余白** — `style.css` の `.hero__title` と `.hero`

新しくカラーコードを直接書きたくなったら、まずトークンとして追加できないか検討してください。
ハードコードを1つ入れた時点で、テーマ切替がその箇所だけ壊れます。
